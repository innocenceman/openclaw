# Plugin Boundaries File Roles

Coverage: `deep-partial`
Freshness: 2026-05-08 repo-native inspection only

| File or path                                            | Role                                                                                                              | Impact notes                                                                                                                                            |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `extensions/*/openclaw.plugin.json`                     | Plugin identity and metadata: `id`, `configSchema`, `channels`, `providers`, auth env/choices, skills, UI hints.  | Drives discovery, bundled metadata, onboarding/config surfaces, provider/channel lists, and contract tests.                                             |
| `extensions/*/package.json`                             | Package name, runtime/dev/peer deps, install behavior, package scripts.                                           | Runtime deps must be installable with `npm install --omit=dev`; `openclaw` belongs in `devDependencies`/`peerDependencies`, not runtime `dependencies`. |
| `extensions/*/index.ts`                                 | Extension entrypoint; exports default plugin entry and registers providers/channels/tools/services or setup flow. | 80 entrypoints observed. Entry helper changes can affect loader/runtime contracts and build output.                                                     |
| `extensions/*/api.ts` and `extensions/*/runtime-api.ts` | Local barrels for extension-internal access to public SDK seams and runtime helpers.                              | Preferred over reaching into core internals or another extension package. Update boundary tests if the allowed seam changes.                            |
| `extensions/*/src/**`                                   | Extension production implementation where present.                                                                | 37 extensions have `src/`; channel plugins commonly split `channel.ts`, `send.ts`, `monitor.ts`, and `setup-surface.ts`.                                |
| `extensions/shared/**`                                  | Shared helper implementations exported through public plugin-SDK extension-shared seams.                          | Support-only directory, not a manifest-backed plugin leaf. Import or behavior changes can fan out across multiple channel plugins.                      |
| `extensions/anthropic-vertex/provider-catalog.ts`       | Support-only provider catalog helper re-exported from `src/plugin-sdk/provider-catalog.ts`.                       | Non-leaf support path that affects Anthropic Vertex catalog injection without owning its own plugin manifest/package.                                   |
| `src/plugins/bundled-plugin-metadata.generated.ts`      | Generated bundled plugin metadata used by runtime/plugin catalog.                                                 | Do not edit generated metadata to silence checks; use generator/check flow when required.                                                               |
| `src/plugins/contracts/**`                              | Plugin registry/discovery/auth/provider/wizard/runtime contract tests and suites.                                 | First stop for shared plugin contract changes.                                                                                                          |
| `src/channels/plugins/contracts/**`                     | Channel plugin manifest/inbound/outbound/group policy contract tests and testkit.                                 | First stop when plugin boundary changes affect channel behavior.                                                                                        |
| `scripts/check-extension-plugin-sdk-boundary.mjs`       | Enforces extension SDK/import boundary modes.                                                                     | Paired with lint scripts such as `lint:extensions:no-src-outside-plugin-sdk`.                                                                           |
| `scripts/check-plugin-extension-import-boundary.mjs`    | Enforces plugin-to-plugin/core import boundary inventory.                                                         | Inventory files are not a safe workaround for semantic boundary failures without explicit approval.                                                     |
| `test/extension-plugin-sdk-boundary.test.ts`            | Test wrapper for extension SDK boundary checks.                                                                   | Run when import seam rules or extension production imports change.                                                                                      |
| `test/plugin-extension-import-boundary.test.ts`         | Test wrapper for cross-extension/core import boundary checks.                                                     | Run when extension package boundaries, support-only helper exports, or inventories are affected.                                                        |
